# 按组件跨品类寻找参考

适用于用户指定的「产品 × 风格」组合缺少整屏参考，或同品类结果高度雷同时。产品任务决定组件职责；视觉偏好决定表现语言。运动不必等于荧光黑底，金融不必等于蓝色，柔和渐变也不只属于冥想。

## 三条检索线

1. **任务线**：同领域产品，用于确认信息优先级、业务语义和主要状态。
2. **组件线**：去掉行业名，搜索具有相同输入、输出、操作和状态的组件；扩展到使用它的其他品类。
3. **视觉线**：独立搜索用户确认的排版、构图、颜色关系与材质。可以与任务线来自不同产品。

在组合需求一开始就并行考虑三条线，不必把同领域搜尽才跨界。先定位缺口，再逐次放宽「行业 → 页面 → 组件」；保留平台、主要动作与关键状态。不要将十几个形容词塞入同一个检索式。

例如：`running active workout pause resume` 找任务关系；`focus timer pause controls` 找组件；`timer soft gradient mobile` 找视觉。Mobbin 等自然语言搜索可写成「大号计时数字，下方有暂停和结束按钮，背景为柔和渐变的计时页面」。搜索结果不证明市场没有某类产品，只说明本轮没有找到匹配样本。

## 组件迁移地图

以下是检索路线，不是声称已经研究了每个品类。具体选用仍须打开画面、核对状态。

| 目标组件 | 可拓宽的品类 | 检索词 | 可借用 | 必须重新判断 |
|---|---|---|---|---|
| 计时、暂停、继续 | 专注、冥想、烹饪、时间管理 | focus timer, stopwatch, countdown, session controls | 数字层级、主次操作、阶段显示 | 正/倒计时、结束确认、后台恢复、户外可读性 |
| 日历、日程 | 预约、旅行、排班、学习 | weekly calendar, agenda, booking slots | 日期选择、时间段、当前日 | 时区、冲突、是否可改期、计划与实际记录 |
| 目标、阶段进度 | 学习、储蓄、会员、下载任务 | goal progress, milestones, step indicator | 当前阶段与下一阶段关系 | 单位、周期、进度依据、是否允许倒退 |
| 实时活动控制 | 音频、录音、直播、通话 | now playing, recording controls, live session | 主要状态突出、暂停/继续、次操作分组 | 快进/循环不能自动移植；结束、取消和退出含义不同 |
| 路线、位置与卡片 | 旅行、出行、配送、房产 | route overview, map bottom sheet | 地图与详情关系、选中点 | 位置权限、隐私、实时与历史路线、定位误差 |
| 统计与历史 | 财务、能耗、时间管理、分析工具 | activity history, analytics chart, period filter | 时间筛选、趋势、明细切换 | 度量定义、缺失值、量纲、图表是否适合数据 |
| 活动/课程/商品卡 | 票务、旅行、学习、电商 | event card, course card, catalog | 图文层级、时间地点、主要操作 | 名额、价格、报名与收藏的区别 |
| 搜索、筛选、排序 | 电商、文件管理、招聘、媒体 | search filters, sort sheet, faceted search | 筛选分组、已选项、清空和结果数 | 字段、默认排序、零结果与持久化 |
| 选择方案、确认提交 | 结账、预约、配置器、订阅 | option selector, order summary, confirmation | 选项与确认区分层、结果摘要 | 付款/扣费/承诺不属于普通选择，不能顺手引入 |
| 社区动态 | 音乐、游戏、学习、创作 | activity feed, community post, challenge feed | 作者、内容、动作分层 | 发布权限、公开范围、内容真实来源 |
| 徽章、奖励 | 教育、会员、游戏、习惯 | achievements, badge collection, reward progress | 达成与未达成状态、阶段反馈 | 不编造成绩、不用装饰奖励替代核心任务 |
| 空态、失败与恢复 | 文件、邮件、出行、上传工具 | empty state, retry, offline state | 当前原因、可恢复操作、保持输入 | 实际错误、权限与数据是否仍在；不抄概念稿编造后台 |

## 完整例子：柔和渐变的运动计时

这是方法演示，不是对既有跑步 App 的修改指令。

- **保留任务**：显示运动已用时间；开始、暂停、继续、结束及保存。是否间歇训练/倒计时取决于需求，不从番茄钟自动加入。
- **组件证据**：[Dribbble Focus Timer](https://dribbble.com/shots/26937453-Modern-Focus-Timer-Task-Management-App-UI) 可见计时主区、下方控制组与浅色渐变环境，是设计展示，不证明可用性。[Refero Touch Time](https://refero.design/screens/0295f7b3-4687-4b50-914c-4ff257365f72) 可见渐变时间卡与独立控制区域，但只看过静态状态。
- **迁移**：借用计时区与操作区的层级，将任务标签、时间语义换为运动数据。去掉无依据的专注任务、白噪音和休息周期。
- **视觉适配**：柔和渐变用于背景或外层；计时数字与按钮使用稳定、高对比表面。保留用户主题色，不能因运动场景改成黑底荧光风。
- **运动约束**：手持操作区域足够、主要按钮易辨认；暂停与结束分开；非意图触碰不能丢失记录；验证亮背景、长时间数字、暂停恢复等真实状态。若后台/GPS 未实现，交付说明不能声称已具备。

其他组合也使用同一逻辑：专业财务工具可以从旅行产品借柔和背景，但表格与金额层级来自财务任务；极简学习产品可以借会员进度分段，但不因此加入促销、付费或游戏奖励。

## 先验行为，再统一视觉

组件来源记录至少包含：`目标任务 → 来源品类/URL/证据类型 → 借用关系 → 保留的状态 → 适配项 → 未验证项`。结构参考与视觉参考可分列，避免假装整屏来自一个竞品。

选型先看输入输出是否相似，再看状态、操作代价、使用环境、平台和密度；视觉相似不能弥补语义冲突。截图只证明可见外观，行为要用可访问流程或文档补证。不要从静态图假定手势、动画或失败恢复。

拼合时固定页面栅格、间距、字体、图标、表面与动作层级。保留组件的业务职责，再将不同来源统一为用户确认的视觉体系；不保留各自品牌造成「拼贴感」。有 Figma 时，此方法只补指定稿缺失的状态或组件，不借机改稿。

## 停止检索与追问

当关键组件的结构与主要状态有依据、视觉方向能统一、已知缺口可列明，就进入实现。没有整屏竞品不构成阻塞，也不需要用户逐个批准正常的跨领域适配。

若仍缺参考，优先采用已有项目组件或成熟平台模式，并把新增部分标为适配设计；不要把未找到参考写成禁止一切设计。只有未知问题会改变核心语义或已确认方向时才问，例如「自由跑正计时，还是分段间歇倒计时？」；已回答的不重问，未得到答案的依赖项不擅自推进。
