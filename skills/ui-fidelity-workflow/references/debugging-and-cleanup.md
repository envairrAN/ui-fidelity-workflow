# 卡住时排查，不继续盲补

同类补丁重复失败、用户说“没变化”、症状转移时，切换到证据排查。两次失败可作提醒，不必等满两次。

定位链：`运行版本 → 复现状态 → DOM/组件 → 生效样式 → 状态写入者 → 帧间交接`。

1. **版本**：核对实际入口、资源 URL/hash/build 与本次产物，检查重复引用、service worker/CDN/browser cache。先定位失配，不直接删所有缓存或旧构建。
2. **复现**：设备、视口、内容、滚动位置、触发方式、是否动画中再点击。复现不了要指出条件差异。
3. **元素**：检查实际 DOM 与 computed style、组件 import、路由分支、重复实例、portal，确认没改错入口。
4. **样式**：记录目标属性的文件、选择器、cascade layer、优先级、顺序、断点、inline style、动画值与 `!important`。源码里存在不等于生效。
5. **状态**：检查组件 state、CSS、手势进度、layout 动画、rAF、timer、observer 与滚动恢复，找同时控制同一值的来源。
6. **实验**：写明原因假设、预期观测、最小改动与结果。一轮只改变一个因果机制；用完清理诊断代码。无证据不一起重写所有可疑模块。

布局测尺寸和滚动，动画看多帧，视觉在同状态对照；rect 或 computed style 本身不能证明材质效果正确。

| 表现 | 优先验证，不能直接认定 |
|---|---|
| 改了没变化 | 旧资源、错误入口、覆盖、不同复现状态 |
| 渐变下又有文字 | 裁切父级和正文高度是否真正关联按钮区 |
| 变矮却下坠 | top、height、transform、scroll 是否同步 |
| 返回闪一下 | remount、初始 opacity、重复入场、交接/滚动恢复 |
| 短距离右滑跳动 | 跟手进度是否被终态直接替换、一级页是否准备过晚 |
| 渐隐无效 | 渲染层提前移除、淡化施加在错误层 |

## 清理须有依据

“旧”和“多”不足以证明可删。将目标分成当前生效、已被替代、必要变体、未确认。对拟删项检查引用与代表状态；动态 class、主题、断点不能靠一次静态搜索判死。

在维护入口合并同组件同状态的冲突规则，清除本轮替换掉的死逻辑、遗留变量与临时诊断。保留有职责的容器；不要以 DOM 少为唯一目标。

源码与构建分别清理。`.next` 可能正被运行进程使用，旧包可能是指定回滚。获授权后先列目标、引用关系、当前运行版和回滚版再精确删除。视觉任务不自动授权依赖升级、架构改动或用户数据删除。

诊断报告给出：证据 → 已确认因果链/候选原因 → 最小修改位置与职责 → 验收/回归 → 未知项。截图不能单独证明具体某一行代码有错。
