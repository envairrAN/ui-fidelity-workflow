# 布局与动画硬约束

## 正文、渐变、按钮

确认谁负责正文可见区域、滚动、渐变和按钮布局。现有元素能承担职责就复用，不要求增加层级。

正文必须有真实空间分配：可见底边不越过按钮上方已确认间距。渐变只做视觉柔化；mask 改变可见像素，但不让布局高度自动缩小。

检查 flex/grid 子项是否被自动最小尺寸撑开；必要时对需要收缩的项设置 `min-height: 0`，让裁切/滚动处于有限尺寸内，不能全局添加。用 gap 或现有布局留出按钮间距，避免绝对定位按钮覆盖无约束正文。

`overflow: hidden` 裁切后仍可程序滚动；`clip` 不提供同样滚动行为。选择取决于要裁切还是要可阅读滚动。固定预览行数可考虑 line-clamp；它不自动解决展开态正文与按钮关系，也不能直接提供连续高度插值。先查实现与兼容性，不把一个属性当成通解。

渐变贴合正文 viewport 边缘，检查定位父级、坐标与滚动关系，不随长正文滚走。装饰层不吞点击、选字或焦点。

## 收起：测两条边，不只测高度

视口 CSS 像素坐标向下为正时：`B(t) = T(t) + H(t)`，即卡片底边等于屏幕顶边位置加可见高度。

“底部不能低于完全展开位置”：`B(t) <= B(0) + ε`。

若用户还要求全程向上：`B(t+Δ) <= B(t) + ε`。

两项要求不同；ε 只能用于明确的测量/亚像素误差，不能掩盖肉眼下坠。高度变小但顶边向下回位更快，底边仍可能先下坠。记录 rect、父 transform、页面 scrollY，确定原因后再改高度、位置或共享进度，不只换 easing，不缩放整卡使文字变形来冒充真实变矮。

布局、位移、裁切、透明度可分层，但同一几何值要有清晰控制者。CSS transition、JS animation、layout animation 与滚动恢复之间需有交接，不同时争写同一属性。

## 返回与右滑

观察：一级页准备 → 二级页退出 → 一级页恢复目标状态 → 二级页卸载。查 key/remount、初始样式复位、入场重复、首帧测量、滚动恢复和完成回调，不直接归罪 z-index。

按钮与手势输入可不同，目标状态及交接应一致。取消回起点；提交从释放时当前进度继续，不能先复位再播放另一条动画。处理指针取消、重复返回与中断，清理迟到回调。

一级页在被遮挡时准备布局和滚动位置。交接不出现空白帧或重复动画。保留必要图层直到退出完成，不以永久双页面覆盖掩盖问题。

## 材质渐隐

先定位折射/高光/模糊对应的渲染元素。若状态改变立即卸载，opacity transition 没有退出时间。

优先在现有材质元素保留退出生命周期并淡出；静态填充按设计进入。只有原结构无法独立控制材质时才新增必要元素并解释。不要把文字图标一起淡掉，不盲目动画昂贵滤镜；处理中断与 reduced-motion，在目标设备观察合成效果。

## 整卡点击与滚动条

折叠卡片可整体展开，同时保留语义清楚、键盘可达的展开按钮及 expanded 状态。不要将多交互 article 粗暴变成嵌套按钮。防止子按钮冒泡触发两次；展开后滚动、选字、链接操作不应误收起。

隐藏滚动条只改变指定滚动容器外观，保留滚动、触控和键盘访问。仅聊天窗保留时，检查实际滚动的是 body、页面还是正文，用明确例外，别用全局 `*` 覆盖后不断补回。

技术语义参考：[MDN overflow](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/overflow)、[MDN min-height](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/min-height)。诊断方法不代表已经确认某个项目的具体根因。
