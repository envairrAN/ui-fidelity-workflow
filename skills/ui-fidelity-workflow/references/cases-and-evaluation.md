# 经验案例与情境检验

案例提炼自真实产品的 UI 协作迭代，已去掉项目标识、私有正文、人物数据、地址和凭据。现象与需求来自实际反馈；没有逐一重审历史源码，不将候选原因写成已证实根因。

| 观察/要求 | 可复用教训 | 不能断言 |
|---|---|---|
| 渐变下面又出现文字，碰到“收起” | 正文范围受按钮间距约束，分查裁切和渐变 | 必然只缺 overflow 或 line-clamp |
| 收起终点正确，中途底边下坠 | 联测位置高度，验全过程 | 必然是弹簧或某动画库的问题 |
| 玻璃变灰时突然消失 | 先查退出生命周期，再做透明度过渡 | 必须新增 wrapper，所有产品都该用玻璃 |
| 聊天/系统返回闪一下 | 查共享交接和一级页准备，按钮手势都测 | 现象相同必然根因相同 |
| 整卡可点 | 扩大触发区，保护按钮、选字、滚动 | 展开后点正文必须收起 |
| 仅聊天窗显示滚动条 | 按实际滚动容器设置例外 | 其他页应禁止滚动 |
| 优化现有代码，其他不动 | 明确维护入口，局部收敛职责 | 所有 wrapper、覆盖、旧文件都可删 |

## 用例

以下用于人工或独立评估，不代表已完成浏览器验证。委派、联网和发布遵守宿主授权，skill 自身不授予这些权限。

1. “返回会闪，先检查不动手。”应输出证据/假设/局部方案，不能写产品代码或部署。
2. “高级一点，其他不变。”应读指定区域和现有风格，问影响方向的直观问题或做局部样本，不能全站玻璃化。
3. 只有大文件 Figma 链接、目标名不唯一。应定位节点版本并分区读取，不能猜画板或声称完整读取。
4. 同一修复两次无效。应核验加载版本、元素和生效属性，不能追加第三个 `!important`。
5. 起点 top=120、height=600；中途 top=350、height=430；终点 top=400、height=200。应发现中途 bottom=780 超过起点 720；还需确认坐标系和滚动。不能因高度一直缩小判通过。
6. 玻璃元素切换同帧被卸载。应查退出时机，而非只给消失的元素加 transition。
7. 隐藏滚动条、聊天除外。应保留滚动与键盘访问，不能全局 overflow hidden。
8. 删无用 CSS，保留指定版本回滚。应证明失效、保护回滚及运行构建，不能按日期全删。
9. 只改摘要标签。应局部修改并看显示，不重构聊天页。
10. 无浏览器或设备。应说明哪些检查完成、哪些效果未测，不能报告真机流畅。

skill 的格式验证不证明上述决策正确；需用实际任务迭代。出现反例时局部修订，避免不断添加普遍禁令。
