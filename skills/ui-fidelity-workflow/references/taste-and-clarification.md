# 审美判断与追问

先明确谁使用、场景与设备、首要任务、内容密度、想形成的感受。高还原以确认过的稿为准；有设计自由度才探索新方向。

## 新建 UI 的四项确认

开始视觉参考检索和实现前，明确产品方向、视觉风格、主题颜色、App/Web。先汇总当前对话已确认项，只问缺项；颜色和风格也属于本 skill 明确的确认要求。可以把颜色和目标端合并成一个问题，问题总数通常不超过三个。用户明确委托决定才可以采用假设，默认选中和超时不算确认。

产品方向不必强迫用户只选一个。若用户将多个目标分配给不同 Tab，记录页面、主任务和入口关系后继续。平台已明确时，普通小间距和断点属于实现决策，不向用户提 CSS 问卷。有稿继承已确认稿；局部修复不重新询问全套产品定位。

## 其他主动澄清的触发条件

先从当前对话、目标区域和现有实现取信息。下面的问题只有在答案未知且会改变方案时才问；不要把它们全部发成问卷。

| 缺口 | 向用户问的具体问题 | 得到答案后转成什么 |
|---|---|---|
| “做一个首页”，没有产品任务 | “用户来到首页最主要是继续任务、查找内容，还是查看进度？” | 首屏主角与主操作 |
| 无平台信息且现有项目无法判断 | “这次优先做手机 App 界面，还是电脑上的工作台？” | 主视口、导航与信息密度；不问 CSS 断点 |
| “卡片 3/4”，参照不明确 | “是卡片占屏幕四分之三，还是占父区域四分之三？指宽度还是高度？” | 明确参照物的尺寸关系 |
| 多稿/需求冲突 | “这一块按新截图的两列，还是保留 Figma 的三列？” | 选定证据优先级，不拼成第四种布局 |
| “点卡片展开”，展开后行为不同 | “展开后点击正文应收起，还是只通过收起按钮关闭，正文可选字？” | 命中区、选字与状态边界 |
| 对局部反馈可能产生两种相反修改 | “你说太挤，是想减少首屏内容，还是保留内容、加强分组？” | 信息量或分组关系，避免直接删内容 |

问题应包含具体对象和可观察的结果，通常 1–3 个，一次问最关键的缺口。有推荐方案时说明理由，但不要把默认选中、沉默或等待超时当作关键答案。对会改变产品含义、交互行为或范围的选择，等答案再做依赖它的实现；期间继续读稿、定位组件等独立工作。

已确认主题后的颜色微调、间距和普通实现参数沿用现有系统或确认的方向，说明重要假设后继续。用户已说“高饱和、黑白对比”就执行，不再问“鲜明还是克制”。缺字体但可临时布局时，明确回退影响，不阻塞所有工作。

收到答案后输出一句可验收描述，例如：“正文可选字，只有收起按钮关闭；展开后不改变整卡滚动位置。”把已回答项保留在当前任务记录，后续不用同义问题反复追问。

“高级”没有固定颜色或圆角。判断主次是否易识别、内容是否便于扫读、排版是否稳定、组件是否一致、材质是否支持层级、动效是否解释变化。参考应指定借用关系，如标题正文对比或图片占比，而不是混搭装饰清单。

无稿新建在完成四项确认后，使用 [视觉实现](modern-product-ui.md) 中与用户选择相符的方向，不自动选择示例风格。

## 用直观问题展开形容词

| 用户说 | 可以追问 | 可观察维度 |
|---|---|---|
| 太生硬 | 是突然换样式，还是移动结尾突然停住？ | opacity、速度、提前卸载 |
| 不够通透 | 希望更多看见背景，还是只减轻边框并保留清晰正文？ | 填充透明度、模糊、对比度 |
| 不顺 | 是拖动不跟手，还是松手后跳了一下？ | 进度、释放速度、接续帧、滚动恢复 |
| 太挤/太散 | 希望一屏更多信息，还是保留信息量、拉开层级？ | 密度、分组、行距、间距 |
| 收起方向不对 | 下边缘是否始终向上？上边缘是否同时回到原位？ | 两条边的屏幕轨迹 |
| 更有设计感 | 想更鲜明还是更克制？参考里最喜欢哪一点？ | 重心、比例、字体、辨识度 |

只问会改变方案的问题，避免整份技术问卷。用户说“3/4”时确认它是目标宽度、上限还是正在抱怨的现象，再写验收。

## 提升判断而非套用风格

允许探索时，做少量真正不同的方向，例如阅读优先与图片主导，而非同一模板换色；说明各自用途和代价。先用代表性页面或组件验证，再推广到授权范围。

检查视觉重心、文字断行和对齐、分组距离、触控/键盘可用性、图标笔画与视觉大小、长短内容稳定性。玻璃、渐变、留白、模糊、动画都要有具体用途；不要把单个产品的风格当作通用标准。

用户已认可整体时，只修被指出的细节。可以解释可用性代价并给局部替代，但不能以个人审美覆盖产品决定。已验证的原始图标和品牌资产优先，不用相似 emoji 或随手绘制替代。
