# 无稿时的现代产品 UI

仅用于无原型的新建界面或已授权重设计。还原稿、既有品牌和用户明确偏好优先。这是本 skill 作者选择的设计方向，不是“所有现代 UI”的定义。

## 先确认，再实现选定风格

开始前完成产品方向、UI 视觉风格、主题颜色、App/Web 四项确认。对话里已有明确答案就沿用；缺项问清，不能因为颜色是可逆参数就自行决定。用户明确委托决定时才可提出并采用合理假设。具体见 [主动澄清](taste-and-clarification.md)。

组件由 [需求](user-needs-and-components.md) 和 [实际参考](reference-led-composition.md) 决定。主任务、信息架构、视觉主角和主操作必须对应，不能先画通用卡片再补需求。

## 可选风格，开放扩展

下列是示例，不限定为三个或四个方向。根据任务主动研究 [开放风格库](visual-style-library.md) 及新的实际产品参考，丰富已确认方向；用户明确极简时排除额外装饰。更多风格不等于一个页面混搭更多风格。

风格与行业独立：柔和渐变可以用于运动，编辑排版也可以用于工作工具。没有同品类整屏时，按 [跨品类组件检索](cross-domain-components.md) 分别寻找任务结构、同功能组件与视觉参考；不为方便检索改掉用户已选风格。

| 已确认风格 | 实现重点 | 避免 |
|---|---|---|
| 极简 / Apple-like | 简单控件、宽松但有任务依据的间距、清楚排版、少量强调色、轻阴影 | 将全部文字做浅灰、用巨大空白挤走操作 |
| 柔和渐变 | 在背景或强调区域组织渐变，正文使用稳定高对比表面 | 模糊渐变覆盖控件、靠透明度降低可读性 |
| 更大胆 / 运动感 | 强明暗对比、关键数字放大、清楚主操作、鲜明主题色 | 所有元素都巨大、装饰口号取代功能 |
| 更专业 | 高效信息密度、稳定对齐、可扫描表格/列表、明确状态 | 将“专业”机械解释为蓝色或复杂仪表盘 |

用户给出的 Apple 风格提示词作为**可选配方**保存：单个 iPhone 15 Pro Max 移动界面；简单 UI、宽松构图、优雅 PingFang 排版；白、浅灰、黑与一个强调色；轻阴影、圆角、大间距、简单图标、平静层级；作品集质量的构图。只有用户选中该方向时启用；多页面任务不能被“single screen”缩减。

## 本作者的强制无稿规范

下列规范按入口的强制设计合同执行。风格形容词不会自动覆盖它们；只有用户明确指定的例外、指定还原稿或已确认品牌冲突才可以调整并记录原因。强对比表示可读与明确层级，不把所有产品都变成黑底运动风；主色使用用户确认的颜色，不从示例表擅自挑选。


| 维度 | 采用 | 默认排除 |
|---|---|---|
| 底色与文字 | 白/中性浅灰配近黑字，或近黑底配近白字；主标题与正文边界明确 | 米黄、奶油、羊皮纸底；灰字叠浅灰底作为整页气质 |
| 主色 | 一个鲜明的非蓝主色，贯穿主操作、当前状态和有意义的进度 | 默认高饱和蓝/电光蓝；莫兰迪主题、满屏多色卡片；只给 logo 上色 |
| 按钮 | 所有按钮采用胶囊轮廓，两端完整半圆；等宽高图标按钮为正圆 | 两侧仍有竖直线段的小圆角矩形；用数学超椭圆替代用户明确要求的半圆端帽 |
| 字体 | 统一 PingFang SC，正文、输入框、按钮、数字均继承；确认实际渲染字体 | 只在 CSS 写字体名却静默回退；混入衬线、手写体或额外英文展示字体 |
| 图标 | 优先已有合规 SVG 资源；新增图标从 GitHub 官方开源图标库取原始 SVG，统一系列，描边默认实际 2px；记录版本、来源、许可证 | 自画 SVG path、字符箭头、emoji、不同图标库混搭 |
| 结构 | 产品任务直接进入首屏；分组、列表、图片与操作各有职责 | 大段情绪口号挤走功能；每段内容都装进同款圆角卡片 |
| 材质 | 每页必须一张突出材质主卡，移动悬浮导航另做液态玻璃；普通按钮和其余卡片平面化，见 [材质与对比](materials-and-contrast.md) | 多处同时堆渐变、内高光、玻璃和投影；返回/关闭按钮仍做高光壳；为凑主角给设置页加装饰 |
| 内容 | 动作、对象、状态、数量清楚；开发限制与示例数据说明放交付文档 | 页面堆灰色小字解释“本地演示、无在线内容、使用什么技术”；无关口号和装饰性英文小标签 |

强黑白对比是明度组织，不强制每个区域都黑底，也不要求所有分隔线浓黑。用户选择柔和或低饱和主题时覆盖鲜明主色的默认偏好；柔和环境仍配清楚文字和操作。用户选择高饱和时，主色需要有可见面积和连续语义，但不能淹没正文、错误状态或图片。危险操作用自己的语义和文字，不靠品牌色冒充警告。

## 已确认对应方向时的配色起始值

以下为本 skill 的原创起始值，**不是从 Mobbin 取样的色值**。只选一组作为主色，按任务和品牌调整；主色之外保留中性底与文字。

| 方向 | 主色填充 | 主色上文字 | 中性底 / 主文字 |
|---|---|---|---|
| 高能运动 | `#C6FF00` | `#111111` | `#111111` / `#FFFFFF` |
| 鲜亮橙强调 | `#FF4D00` | `#111111` | `#FFFFFF` / `#111111` |
| 深橙内容卡 | `#D34200` → `#B52F06` | `#FFFFFF` | `#FFFFFF` / `#111111` |

颜色尚未确认时先提问；这些数值只细化用户已选择的颜色方向。不把上一轮配色当通用品牌答案。按钮 CSS 可用 `border-radius:9999px`，保证宽度不小于高度，检查最终四角半径至少为高度的一半；图标按钮采用等宽高。检查导航、筛选、次操作、空态和弹窗按钮，不能只改主按钮。

PingFang 不可用时，先检查用户已有字体资产与可用字重；不要从不明站点下载或擅自将字体打包发布。明确告知缺失并请求合法字体来源，临时回退须标记为未满足要求。使用实际渲染字体检查，不能仅凭 `font-family` 或资源 loaded 声称通过。

新增图标可从 [Lucide](https://github.com/lucide-icons/lucide) 等官方开源仓库按需取描边 SVG，无需安装整套包；保留许可证与可追溯提交。允许改尺寸和继承颜色，不自行重画路径。图标按钮仍须有可访问名称。实际 2px 不等于 viewBox 中的 2 单位；缩放与非缩放描边按 [材质与图标](materials-and-contrast.md) 核查。

删除的是不帮助用户完成任务的解释性小字。作者、价格、必要字段标签、操作错误和空态下一步属于产品信息，保留并清楚呈现；不要把“不要说明文字”误解成删除必要反馈。样本使用虚构/占位内容时在交付记录明确说明，不把它伪装成真实业务结果。

不要假定鲜艳底色都能配白字。普通正文按实际前景/背景检查至少 4.5:1，大字至少 3:1；识别控件或状态所需的非文字视觉信息按适用条件检查 3:1。透明、图片、渐变背景须检查实际组合。依据：[WCAG 文字对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文字对比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。这些阈值不等于完整可访问性合规。

## 从参考提取关系，不复制整屏

按“同任务 → 同组件 → 同状态”找参考，这里的“同”不要求同行业。记录来源、实际看到的画面、借用关系、适配后的语义与不适用部分。可读取 [跨品类证据册](reference-atlas.md) 或旧有 [Mobbin 公开预览笔记](mobbin-pattern-notes.md)。新建界面须完成与本轮任务有关的参考检索和实际观察；可复用已核实且适用的记录，不把登录/付费库当作已读材料。

例如：借用结账页“选择项与提交按钮分层”的关系，不能把结账样式硬套到书架；借用分类栏“文字 + 图标 + 下划线”的选中表达，不能只复制它的颜色。让主色承担自己的产品语义。

## 实现与自检

先完成一张代表性页面及其最重要状态，再扩展授权范围。无需等用户批准已明确授权的常规实现。建立少量语义变量：背景、表面、主/次文字、边界、主色、主色上文字；不为样本搭建大型设计系统。

在真实渲染后检查以下五项，失败就做针对性修正：

1. **任务层级**：第一眼能定位主要内容和下一步；首屏没有被无关口号、巨大空白或同权卡片占据。
2. **风格辨识**：符合用户已确认的风格与主题，不能把所有方向都改成高饱和运动风。移除颜色后，结构仍能解释主次。
3. **可读性**：核实 PingFang 实际生效；主文、次文、占位符与按钮检查真实对比；删掉无助于任务的灰色小字，不靠过小字或裁掉内容保持一行。
4. **状态与交互**：检查所有按钮的半圆端帽和图标来源；选中不只靠颜色；实际点击、焦点可见、空结果、长标题等任务相关状态工作正常。装饰不抢操作。
5. **适配**：在目标视口和一个较窄视口检查溢出、阅读顺序、操作遮挡。桌面采用有效工作区，移动端重排而非整体缩小。

交付页面截图、可运行入口、主要设计理由及实际检查结果。不要把五项检查算成“设计质量 100 分”；符合风格也不证明优于基线，审美优势仍需盲评和独立对照。
