# 从设计证据到实现

## 对齐来源

记录链接、file/page/frame/node、版本或获取时间、视口、主题、组件状态。文件链接不等于指定画板：先取结构定位，再取该节点的设计信息和截图。节点名相同不等于版本相同。

近期用户批注修正 Figma 时，以批注涉及的部分为准，其余遵循已确认设计。实现任务默认只读 Figma，读稿不授予改稿权限。

## 有 Figma 连接时

使用当前工具实际提供的能力，获得以下必要证据；这些是能力描述，不是所有客户端通用的 API 名称：

1. **节点截图**：比例、视觉层级与遮挡关系。
2. **设计上下文**：图层树、Auto Layout、padding/gap、固定/Hug/Fill 尺寸、约束、裁切与定位。
3. **样式来源**：字体/字重/行高/字距、颜色及透明度、描边/阴影/模糊、变量绑定与当前 mode。
4. **组件来源**：主组件、实例覆盖、variant、交互状态、Code Connect 或现有代码组件映射。
5. **原始资源**：图标、图片、SVG。优先复用正确资源，核对导出范围、裁切与权限。

大画板先定位再分区读取，最后用整体截图检查组合关系。输出截断则缩小节点范围，不宣称读完。资源或节点缺失时说明具体缺口。

Figma 生成代码只是设计证据和实现草稿；适配现有技术栈、组件及状态，不替换项目结构。存在 Code Connect 映射时，先检查实际实现与 props，不重复创建组件。

## 无连接或只有截图

说明只能观察像素结果。必要时请求画板导出、字体、资源或标注；仍可先判断层级和比例。不能声称读到了真实 token 或 Auto Layout。

截图像素不直接等于 CSS px。确认是否缩放、DPR、浏览器缩放、状态栏/工具栏和网页实际视口。不要将手机系统 UI 当成网页的一部分。仅有单一尺寸时，其他尺寸的响应方式依据现有系统推断并注明，关键歧义再问。

## 最小映射与还原顺序

按区域列：`设计元素 → 现有组件 → token/测量值 → 差异 → 本轮改法`。没有对应 token 才增加必要变量，不为一处修复搭新设计系统。

字体也是几何：先确认实际加载字体、字重和回退，再判断换行与宽度。不要用大量手工换行补偿错误字体，不未经允许改文案凑高度。

Auto Layout 通常可映射为 Flex/Grid 与 gap，不必逐图层复制。浮层、徽标可合理定位，主内容不要只靠截图坐标。按职责处理 safe area、键盘避让、导航与内容内边距。

顺序：骨架/内容密度 → 大小与间距 → 字体和断行 → 色彩透明度 → 图标材质 → 状态交互动效。先修改变视觉重心的偏差，再打磨阴影。

同视口、同内容、同字体状态截图。可并排、叠加、差分；考虑字体抗锯齿与动态内容噪声。图像相似不等于交互正确，更不证明后端能力已接通。

官方参考：[Figma MCP](https://developers.figma.com/docs/figma-mcp-server/) 提供设计上下文、组件、变量及 Code Connect 能力；具体可用工具以当前环境为准。范围控制和验收是经验方法。
