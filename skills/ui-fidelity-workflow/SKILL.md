# UI Fidelity Workflow

两部分：先确定为什么需要这些页面与组件，再依据用户确认的视觉方向和真实参考实现。不要凭“跑步/阅读/高级”等词自行定义产品，不用通用卡片模板代替需求分析。

## 加载与执行约定

Read this entire file before acting. Follow the task-specific route and load its required references before each relevant stage. Treat applicable requirements as acceptance criteria; do not claim compliance without observed evidence.

- 本文件是执行入口，README 和技能描述不能替代它。相关文档路径以本文件所在目录为基准；必读文件缺失时先补齐，不能自行猜测内容。
- 开始前确定无稿创建、有稿还原或局部修复，列出本轮适用检查项；按下方路径分阶段读取，不一次加载全部资料。
- 完成后逐项给出证据；必要项失败先修复，受限而未验证则明确说明，不能将未完成记为通过。所有要求独立于历史聊天或账号记忆生效。

用户明确调用本 skill 时，下列规范是本轮 UI 设计与交付的约束，优先于模型的默认审美、通用模板和自行选择的组件习惯。不能把“潮流 / 极简 / 更专业”等风格词当作取消这些约束的授权。只有用户明确修改某条规则，或指定的还原稿/既有品牌确实与它冲突，才记录并采用该例外；不从“自由设计、可使用素材”等笼统描述推断豁免。遵守宿主的系统、安全与执行权限；skill 不授予额外权限。

用户要求只检查时不改代码；局部修改不扩大为全站重设计；实现授权不等于发布授权。无原型新建界面执行下面的完整合同；已有页面的小改动只检查受影响规则。

## 无原型界面的强制设计合同

以下是当前跨产品规则，不依赖作者账号记忆；有指定还原稿或用户明确修改时记录例外。

| 规则 | 必须实现与检查 |
|---|---|
| 需求先于组件 | 明确每页的主任务、用户可控制的输入/选择、关键失败/恢复、成功后下一步；记录 `需求 → 产品判断 → 组件 → 状态 → 验收`。产品判断说明依据与取舍；没有研究就标设计推断，不能写虚构洞察。没有任务依据的大横幅、装饰指标、口号不进入首屏。 |
| 先看组件再写 UI | 优先实际查看用户指定的 Mobbin；按任务找发现/输入/版本对比/发布等具体组件与状态，缺整屏就跨品类查单个组件。每个关键组件绑定具体来源链接、已看画面和采用的结构；禁止先自由画完，再贴参考链接。组件组合完成后统一视觉。 |
| 来源受限 | Mobbin 被登录/付费限制时记录实际失败，不冒称已看；用户已允许公开网站时使用明确标注的公开产品参考，若用户只接受 Mobbin 就追问替代来源。未经授权不购买、绕过或登录新服务。只有文字摘要不算看过组件。 |
| 胶囊按钮 | 所有常规按钮、筛选、次操作、弹层按钮、导航选中按钮：两端完整半圆，最终圆角至少为高度的一半；等宽高图标按钮为正圆。不能只改主 CTA。可点击整行/卡片用对应列表、链接或选择语义，不把矩形按钮换个类名逃避检查。 |
| 元素对齐自检 | 交付前必须检查文字/数字/图标相对容器的水平与垂直中心、同组基线、边距及重复组件一致性；圆形编号、徽标和图标按钮逐个检查，不能只测外框。SVG 编号使用容器中心与明确的锚点/基线，避免手写偏移猜位置。按 [验收](references/verification.md) 在实际字体、尺寸和状态下测量并目视复核，不对齐先修复。 |
| 中性底色 | 页面与普通内容表面用白、中性灰或黑；禁止米黄、奶油、羊皮纸、黄绿色灰充当中性底。主题色只用于有语义的强调区域，不把浅黄绿底说成“白色”。黑/白文字按真实表面明度成对检查。 |
| 主题色与字体 | 主题色采用用户确认值；未指定时追问，不自动套高饱和蓝。统一 PingFang SC，包含英文、数字和表单控件；检查实际渲染字体。缺合法字体就明确未满足，不能静默回退后称完成。品牌图像中的原文字不冒充界面字体。 |
| 开源图标 | 使用已核查的 GitHub 官方开源 SVG 原始几何；统一系列和实际 2 CSS px 描边，保留来源/版本/许可。禁止自己画替代 path、字符箭头或 emoji 图标。 |
| 移动 Tab bar | 必须是一个整体的底部悬浮胶囊：左右和底部可见留空、完整半圆外轮廓，全部 Tab 在同一容器中；不能做贴底满宽矩形栏。外壳必须实现液态玻璃视觉：背景透射与模糊、边缘高光、内反光与悬浮阴影，不能只用白底加投影代替。考虑安全区，滚动到底的主操作不能被遮挡。切页、滚动后切换及快速连点时，Tab bar 的视口位置必须稳定；逐帧检查动画中间态，不得因临时横向滚动条而上下弹动。桌面导航按 Web 任务组织。 |
| 材质克制 | 每页必须有且仅有一张明显材质主卡；前景弹层最多一个材质主角；普通按钮纯色，不加玻璃壳、渐变或装饰投影。液态玻璃悬浮导航为独立功能层，不占内容卡片名额。每个有内容的页面必须指定且实现一张突出材质的主卡，不能省略。 |
| 导航状态 | 未选中 Tab 透明，不做 hover 黑底或按压缩放；选中项的背景、文字、图标成对定义，禁止黑底黑字。保留键盘 focus-visible。 |
| 产品文案 | 删除无助于任务的灰色解释小字、技术说明和装饰英文标签。保留作者/时长、表单标签、操作状态与必要能力边界；演示声明放适当的一处和交付材料，不重复铺满界面。 |
| 可运行的基础动画 | 新建可交互界面必须交付实际页面切换、按钮按压和新增内容进入动画；有数值变化、完成图标时接入真实数值滚动与开源 SVG 路径动画。按任务选用，不加假统计。必须查看中间帧或录屏、测连续点击和 reduced-motion；写 CSS 或展示静态终点截图不算完成。 |

## 两条执行路径

### 无原型：需求与参考驱动

1. **确定任务。** 读取 [需求到组件](references/user-needs-and-components.md)，区分明确要求、观察事实、设计推断；整理 `需求 → 产品判断 → 页面/动作 → 组件/状态 → 验收`，不虚构用户研究。
2. **确认四项。** 产品方向、视觉风格、主题颜色、App/Web。已有答案不重问；仅追问会影响实现的缺口，每次 1–3 个直观问题。关键答案未到时，不用默认值、沉默或超时替用户决定。局部修改继承既有方向。
3. **先查看参考。** 必读 [参考驱动组合](references/reference-led-composition.md)。分别按任务、组件与风格检索；没有同类整屏时用 [跨品类组件](references/cross-domain-components.md)，如运动计时借鉴专注工具，但保留运动语义。来源受限如实记录，不冒称看过 Mobbin。
4. **记录再组合。** 实现前记录具体链接、已看画面、采用的组件关系和适配。可复用已有或许可允许的源码；只有截图时复用模式后实现，不宣称拿到竞品源码，不搬品牌资产。
5. **统一视觉。** 必读 [视觉实现](references/modern-product-ui.md) 与 [材质及对比](references/materials-and-contrast.md)，执行上表。风格来自需求与参考，不固定套某一种产品构图。极简可收敛强度，不自动取消强制项；明确全平面等用户要求则记录例外。
6. **实现状态与动效。** 完成主要任务及空、忙、错误、恢复、完成状态；读取 [动效配方](references/motion-recipes.md)，使用现有动画系统或包内 [CSS](assets/motion/motion.css) / [Web Animations 模块](assets/motion/motion.mjs)，不新增无关依赖。导航无悬停/按压装饰；普通操作有必要反馈，数字只响应真实变化。
7. **执行验收。** 必读 [验收清单](references/verification.md)。同尺寸检查页面、状态、对齐、颜色与参考关系，动画检查中间帧、快速连点与 reduce；不能只检查代码声明或静态终点。

### 有 Figma / 截图：设计还原

遵循 [Figma 与截图还原](references/figma-and-fidelity.md)：先明确目标、状态、视口与版本；读取设计证据、资源和已有组件，再按结构、几何、排版、颜色材质与动效逐项还原。已确认原稿优先于无稿默认风格；缺字段说明未知，不猜成精确值。偏差用 [还原诊断表](references/fidelity-diagnostics.md) 定位，保留原有业务逻辑与数据边界。

## 局部修复与沟通

只读取与目标有关的文件，优先修改现有实现。用户只检查就不改代码，范围明确就直接执行，不借小改动重做产品或全量构建。

- 模糊视觉反馈：[审美与主动澄清](references/taste-and-clarification.md)。
- 裁切、返回、Tab 上弹与动画交接：[布局与动画](references/motion-and-layout.md)。
- 多次修复失败、版本与重复样式：[排查与清理](references/debugging-and-cleanup.md)。
- 扩展视觉方向：[风格库](references/visual-style-library.md)、[参考证据册](references/reference-atlas.md)。
- 方法与许可：[来源及采用范围](references/adopted-methods.md)。
- 行为反例与评估设计：[情境检验](references/cases-and-evaluation.md)。

## 交付门槛

交付实际页面、需求/组件来源记录和逐项 `通过 / 失败 / 未验证 / 不适用及原因`。功能能用不等于 skill 合格；未落实强制项先修复，预算不足就明确未完成，不算合格实验样本。

[只读几何诊断](scripts/browser-contract.mjs) 可检查部分按钮、表面与导航几何，不能代替字体、光学对齐、玻璃、来源和动画的实际核验。开发说明留在交付材料，界面保留必要状态、错误与能力边界。

首稿、人工迭代稿、独立对照分开记录；不编造审美评分、还原百分比、新账号实测或效果提升。未经用户明确要求，不发布、不下载整套额外 skill、不扩大清理范围。
